# Projects

Projects (`spaces` in code), their coordinator, threads and project files. Linked from [AGENTS.md](../../AGENTS.md).

- Projects (`spaces` in code, "Projects" in the UI): `src/services/spaces.ts` keeps projects, their repositories and threads (tasks with `space_id`), and starts threads within the project's parallel limit, queueing the rest with their brief (`drainQueue`). `src/core/thread-state.ts` derives each task's state (waiting, working, queued, review, landing, idle, resolved), a thread's or a task of its own, for the server and every page alike: the sidebar draws and filters tasks by it (`TaskStatusIcon`, the Status facet in `task-view.ts`), with whether the sandbox runs as a facet of its own. A task whose reply delivered what was asked (judged by the decision model, `closeIfFinished` in `thread-reports.ts`, as the reply ends and so as it is about to stand, not as working) is resolved, shown as Done, and the next message it is given reopens it; an answer or an offer of more leaves it open. A scheduled routine's run (`automationId` on the task) is done once it replies without asking you. Tasks are named in a few words by a fast model (`src/services/titles.ts`, the `TextModel` port, `ANTON_TITLE_MODEL`) from their first message, else by its start; a routine is named once (`title` on the automation) and each run is titled with it and its day. The Coordinator agent (`src/agents/coordinator.ts`, instance id = project id) plans and starts threads; `src/services/coordinator.ts` primes it with the project's state, which reaches it as a `project-state` signal after each message it has changed for (and every tenth message regardless; `useProjectState`), never in its instructions, so they stay the same and its prompt cache holds, and `thread-reports.ts` tells it what changed, batched and once per state, and of each thread a routine starts. Project files (`space-files.ts`) are copied into each thread's machine at `../project-files`, each time it is set up, skipping a file the machine already holds unchanged; the project's Library panel is a task's Library (`Library` in `library-tab.tsx`, given a `LibrarySource`) over those files, with each thread's own under From threads, a folder each named for it (with its day when titles repeat) and Anton's own `renders/` and `images/` left out of the path (`src/web/lib/project-library.ts`). A thread's own Library shows them too, under Project files. Deleting a thread (`deleteTask` in `spaces.ts`, one at a time per task) is refused while it is resolved (reopen it first), keeps the files it saved as project files under `From threads/<title>/` (`keepThreadFiles`), and drops it from the coordinator's feed; the coordinator's state lists it as deleted for a week (`deleted-threads.ts`), so a follow-up meant for it starts a new thread rather than a message that fails. The coordinator's `read_thread` also says what a thread is doing now and for how long, with its running subagents (`threadActivity`), so a stuck one is seen. The coordinator's `start_thread` and `message_thread` attach the project files a brief names, or else those attached to the user's message it answers (`filesForThread`), and a sandbox's `read` shows an image as a picture, or in the vision model's words for a model that cannot see, and its `edit` takes several changes to a file in one call (`edits`, made in order and written once, or not at all) so known changes cost one model call, not one each (`src/flue/sandbox-tools.ts`). A project's mark is a drawn icon and tint from `project-icon.tsx` (saved as `rocket` or `rocket:violet`; never an emoji). Each state draws as a glyph (`thread-glyph.tsx`), and `project-viz.tsx` holds the project's charts: the Pulse (the open count beside a sentence on what the project comes to, a strip of its threads by state, and its bay in the rack), wait tracks, the schedule and spend in Overview, and the state split on cards and in the sidebar; threads a reply started show in the feed as a live card each (`ThreadRow` in `thread-card.tsx`: glyph, title, then while it works the step of its todo list in hand with how many are done, else what its agent does this moment (`useThreadNow`, from the `todos` and `now` changes; `nowText` in `src/web/lib/now-text.ts`), else what it last said; pull request, needs-you and file chips; a thread that waits on you or is ready for review opens out with its question or last words and its next steps as buttons; the rest in a hover peek), and the coordinator names a thread in its words as `[title](#thread-<id>)`, drawn as a `ThreadChip` through markdown's `InlineLinks`. `project-rack.tsx` puts projects in the rack drawing the Tasks page uses (`RackWell` in `task-rack.tsx`): each project a bay, its threads the blades, drawn out on a point with a card to answer or open them; the Projects page shows every project, Overview the project's own bay. `ProjectRouteArt` (`illustrations.tsx`) draws plan, threads, review and done like the New task page's route, taking turns on a new project's empty feed. The pages are `project-page.tsx` (coordinator feed and `project-panel.tsx`, or a thread with its own panels), `project-sidebar.tsx`, `projects-page.tsx` and `project-settings.tsx`.
