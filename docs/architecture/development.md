# Development notes

Linked from [AGENTS.md](../../AGENTS.md).

- `npm install` runs `scripts/patch-flue.ts`, which patches Flue bugs: duplicate skill names with `.agents/skills`, subagents copying their parent's compaction reserve, `flue.db` opened without a busy timeout, and transactions opened with a plain `BEGIN` (a reader is refused a held write lock at once whatever the timeout, so they open with `BEGIN IMMEDIATE`). Drop each patch once Flue fixes it.
- `npm run lint:hooks` runs oxlint's React hooks rules on `src/web` (`.oxlintrc.json`), in CI too. Breaking the rules of hooks fails it; a missing effect dependency is only a warning, since some effects leave one out on purpose.
- `npm run ui:fixture` serves the real UI on Vite with `@flue/sdk` swapped for scripted conversations (`scripts/ui/chat-sdk.ts`) and the API mocked (`scripts/perf/mock-api.ts`). A request with no mocked answer logs `[perf] unmocked`; a page that reads a field of that empty answer fails, so add the answer there. In a task's sandbox it binds the first of `$ANTON_PREVIEW_PORTS` (so Preview shows it), else `UI_FIXTURE_PORT` or 43160. Every conversation (`/agents/perf-task`, `/incognito`, a project's coordinator) starts with 8 long turns (`?turns=0` or `?turns=20` to change it). A Playwright script drives it through `window.__chat`: `send(text?, { chars, ms })` and `reply(...)` resolve once the reply settles; `streaming()` and `info()` report. Use it to check layout, scrolling and streaming in seconds.
- `scripts/perf/profile.ts` profiles a task page in Chromium with a scripted reply (no keys); it uses `PERF_CHROMIUM`, else the newest Chromium under `/opt/pw-browsers`.
- `npx flue run src/agents/coder/index.ts --message "Say ready."` tries the Coder (needs an LLM key).
- Production: `npm run build && npm start` on `PORT`. `npm run start:backup` (`scripts/start-with-backup.sh`, settings in `litestream.yml`) needs Litestream 0.5+ and the Tigris variables: it restores `anton.db` and `flue.db` from `db/` in the bucket when the server has none, then runs Anton under Litestream (writes streamed every 30 s, the last flushed on a clean stop). If the restore fails Anton does not start, since an empty database beside existing storage would lose every task. Only one server may run against a bucket at a time.
