# Models and plans

Linked from [AGENTS.md](../../AGENTS.md).

- `src/services/subscriptions.ts` — plans signed in from Settings › Subscriptions: keeps and renews each sign-in, adds the plan's models, counts use (`planUsage`).
- Claude plans run Claude Code on the server, signed in through its own `auth login` (`docs/claude-code-subscription.md`). Anton never holds that token and never passes Claude Code an API key or `CLAUDE_CODE_OAUTH_TOKEN`. Key plans keep their key in settings, never in a machine.
- Gateways: OpenRouter (pasted key, else `OPENROUTER_API_KEY`) and Vercel AI Gateway (`gateways` in `src/providers/index.ts`). A model choice's route (`src/core/model-route.ts`) is `<model>#via=<slug>` or `#sort=<sort>`; usage counts it under the plain model. The shared picker round-trips these specifiers in settings, project choices and automations; task records keep their existing plain model and separate route, decoded on creation. Runtime specifiers for helpers, coordinators and compaction are registered by scope before resolution (`src/core/routed-models.ts`); the registry never chooses a route for a call. Only the caller's selected specifier does.
- A model's maker, for its tool profile ([agents](agents.md)), is told from its specifier alone (`madeByOpenAi` in `src/core/tool-profile.ts`), never from the model list, so it never waits on a vendor and is the same on every render: a ChatGPT plan's models (`openai/`) are OpenAI's and Claude Code's Anthropic's; on OpenRouter and Vercel the maker is the id's first part (`openrouter/openai/...`, `openrouter/~openai/...`); on plans that serve several makers (Cursor, OpenCode Go) it is the model's name (`gpt-`, `codex`, `o3`), as their own model lists name the vendor. Routes and variants are left out. So GPT and Codex models get `apply_patch` however they are reached, Cursor's GPT models among them, and Claude, Composer and the rest keep `edit`.
- Variants: `<model>[1m]`, `<model>[fast]` and both are models of their own (`src/core/model-variants.ts`); fast on ChatGPT sends `service_tier: "priority"`.
- A reply failing on a non-default model offers Retry on the default (`isPlanRefusal`, `switchToFallbackModel`). Nothing switches by itself, since another model may bill another account.
- Background models (`backgroundModels` in `src/services/general.ts`): web digests, screen reading, compaction summaries; digests and screen reading must be OpenRouter models. Each keeps the effort picked with it (`backgroundReasoning`), sent as OpenRouter's `reasoning.effort` for digests and screen reading and as the compaction summary's reasoning (a Flue patch in `scripts/patch-flue.ts`). With no compaction model chosen the conversation's own model writes the summary, the one model certain to be reachable on its plan or gateway, at `low` (`COMPACTION_SUMMARY_EFFORT`), through the same patch, which each plan's model (Claude Code, ChatGPT, Cursor, OpenCode Go) takes through its own map of levels, as it takes the task's thinking level. A subagent on its own model writes its summary with that model at the same effort.
- `src/services/decisions.ts` — the decision model (yes/no and choices with probabilities, a fraction of a cent). Everything that uses it must behave as before without it.
