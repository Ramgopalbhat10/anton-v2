# Replies, artifacts and attachments

Linked from [AGENTS.md](../../AGENTS.md). Components are in `src/web/components/`.

- Replies (`thread/thread.tsx`) render markdown with `@pierre/highlights` (`content/code-block.tsx`; `src/web/lib/highlight.ts` paints tokens with `--syntax-*` variables, so code follows the theme without re-highlighting), mermaid (`content/mermaid-diagram.tsx`), `path:line` links into Files, `ask` cards (`thread/reply-cards.tsx`) and output cards for `../outputs/…` (`src/core/outputs.ts`, viewer in `content/output-viewer.tsx`).
- The shared output viewer portals into `WorkspacePane` on desktop. Opening an artifact temporarily opens that workspace without changing its saved open/tab choice. `VmPanel` mounts only the dock until the workspace itself is opened (`contentOpen`); a viewer must not initialize a saved Terminal and start a sandbox. Already-mounted content stays mounted but hidden. Phone widths (`useOnePane`) and pages without a workspace use an inset, safe-area-aware sheet. Viewer and conversation headers share `h-11`; viewer controls adapt to their container width, not the screen width.
- An artifact uses the workspace's slide when the column opens or widens; in an already wide column the viewer slides in without resizing the conversation. Source previews keep the gutter pinned and scroll both axes in one viewport, so the horizontal scrollbar stays below the visible code, not below the last line of the file.
- `show` draws a card from a fixed catalog (`src/core/ui-spec.ts`, checked by `src/services/artifacts/show.ts`). `render_html` saves one page under `renders/` (`src/services/artifacts/renders.ts`).
- A rendered page reaches no network itself: a CSP allows no requests, it talks to the thread over the MCP Apps postMessage protocol, and its `fetch()` goes through Anton (`src/services/browser/page-fetch.ts`: public addresses only, no cookies, size and time limits). Its state lives on the server (`src/db/pages.ts`), so every copy shows the same state.
- `generate_image` (`src/services/artifacts/images.ts`, `ImageModel` port) needs an OpenRouter key; images go under `images/`.
- The Artifacts page (`pages/artifacts-page.tsx`, `src/services/artifacts/artifacts.ts`) lists what agents made, indexed in `output_index`. Deleting one (`removeOutput` in `src/services/artifacts/files.ts`) records it in `deleted_outputs`, and replies that showed it say so rather than break. Add files keeps the user's own files there (`src/services/artifacts/added-files.ts`); a SKILL.md or skill .zip installs as a skill ([agents](agents.md)). + › From Artifacts in a composer attaches one to the message.
- Attachments (`composer/attachments.tsx`, `src/services/artifacts/attachments.ts`, `src/services/artifacts/documents.ts`): non-image files are saved under `uploads/` and read as text, cut at 20,000 characters in the message; the agent reads the rest with `read_attachment`.
- Pictures sent with a message (`thread/sent-images.tsx`) draw in both the thread and the coordinator. A picture keeps its element while its source changes from the `data:` URL the page sent to the URL the conversation stored, and swaps only once the new one has decoded; a message waiting on uploads (`PendingMessage`) shows the same pictures and file chips, so the handover does not blink. An image's Library chip is left out beside its picture. Clicking one opens the output viewer with a `src` item (`ViewerItem.src`), which is not in any task's Library.
