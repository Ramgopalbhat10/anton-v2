# Context, compaction and traces

Linked from [AGENTS.md](../../AGENTS.md). Every model call resends the whole conversation, so most rules here keep it small and the prompt cache warm.

## Compaction

- `src/services/context/context-usage.ts`: the context meter and where agents compact (`compactionFor`). Settings › General's Compact at (200K default), and Compact Claude Code at for Claude Code's models (`compactionCeilingFor`). The summary comes from the chosen compaction model and effort, else the agent's own model at `low` (`COMPACTION_SUMMARY_EFFORT`): the summary call shares no cached prefix and the reply waits on it. A compaction keeps a fifth of the context word for word (`keptAfterCompaction`), so the agent does not reread its files.
- `src/services/replies/compaction-pin.ts`: after a compaction of the Coder's main conversation (runtime `compaction` event, `noteCompaction`, kept in `task_gate_state`), the agent gets its request (`requestFor`, cut past 12,000 characters) and its saved todo list (numbered from 1 as `update_todos`'s `changes` counts, with status and evidence) word for word in one `reminder` signal, once per compaction. Summaries paraphrased the exact words the end-of-reply checks hold the agent to.
  - Flue lets Anton add a message only from a reply's start and finish hooks, so the pin rides ahead of whatever the finish hook next sends back, else after the next message the agent gets. It omits the request when that message is the user's and starts the reply (it then is the request); a message joining a running reply is not the request, so the request goes with it.
  - Never sent alone at a reply's end (a whole extra model call), never in the system prompt or a tool description. Chats, plan mode and reviews get it; subagents and incognito chats do not.

## Cutting and pruning

- `src/flue/tool-result-cut.ts`: tool results past 50KB, web searches past 12KB, fetches past 24KB (`LIMITS`); the agent reads on with `read_full_result` (`src/services/context/tool-results.ts`). `bash` cuts its own output at 16KB (`src/flue/shell-tool.ts`). Long web results are digested by a fast model when that pays (`digestPays` in `src/services/context/web-digest.ts`).
- `src/services/context/context-prune.ts`: past half the compaction point, old tool results become one-line stubs, in batches that pay back their cache miss (`warmShare`). The cache is cold once idle past its lifetime (`cacheLifetime` in `src/core/prompt-cache.ts`: 10 min on OpenAI, 5 elsewhere). Size is the provider's count of the previous call (`noteSent`) plus an estimate since; the estimate alone sizes a first call or one after compaction.
- Cleared stays cleared so the cache holds. The set is in memory, keyed by the runtime's conversation name (which says nothing of the task), so after a restart a task clears afresh and misses once.
- Stale pickup: a conversation resumed `STALE_MS` (3 h) or more after its newest message is cleared at any size, keeping only the newest 20K tokens of results, in one batch on the first call (its cache is gone, so the batch costs nothing). Three hours, not the cache lifetime, because measured over 18 days OpenAI's cache still held on 75% of calls 10–20 min apart, 65% up to 1 h, 33% up to 3 h, none after a day; clearing at the lifetime would have missed a held cache in 15 of 37 batches. Do not lower `STALE_MS` or widen the rule to every cold call without replaying real tasks.
- Never prune on Claude Code or Cursor, and never drop reasoning on the Responses API.

## Cache stability

- Anything that changes a running task's system prompt or tool list busts its cache: connectors are reached through tools for that reason, and repo notes and project memory are read once per task. A repository task has its sandbox's tools from its first call and its repository's instructions from its base commit, so the sandbox starting changes neither ([agents](agents.md)); `tests/task-files.test.ts` renders the Coder both ways and compares.
- `src/services/context/response-trace.ts`: each Coder reply's trace (model calls by prompt part, cache reads and writes, tool calls, subagents) in `response_traces` (latest 100 per task); `cacheVerdict` explains each hit or miss. A reply resumed after a restart runs no start hook, so its trace begins at the next model call and is marked `resumed`.
- `src/services/replies/settled-reply.ts`: a reply that fails (a plan's limit, a provider error) or is stopped never runs its finish hook, so its message carries no trace or usage. On its `submission_settled` the trace and usage are saved with what the hook would have attached (`settled` on the trace, by every submission that settled with it); the thread fetches them for a reply whose settlement was not `completed` (`/api/sessions/:id/settled/:submission`).
- `npm run cache:misses` classes misses from traces (`missClass` in `src/core/prompt-cache.ts`; `--run` reads a benchmark folder). `provider miss` and `older prefix` are the provider's best effort (a few percent of calls miss seconds after a hit); `compacted`, `pruned` and `model changed` are Anton's choice; `expired` is a gap past the lifetime. A `prompt changed` or `tools changed` miss inside a reply is a render bug: compare the two calls' prompts and tool lists in the trace.
