# Replies, artifacts and attachments

What a reply can draw, the Artifacts page, and files attached to messages. Linked from [AGENTS.md](../../AGENTS.md).

- Replies draw more than text. Markdown code blocks are highlighted with Shiki once the text settles (`code-block.tsx`), ```` ```mermaid ```` blocks draw as diagrams (`mermaid-diagram.tsx`, lazily loaded, strict security), and a `path:line` in inline code opens Files at that line (`focusFile` in `workspace.ts`). The Coder's `ask` tool puts a question as a card of options (`reply-cards.tsx`; `asks.ts` hands the question to `reply-check.ts`, so the task waits on you), and once answered the card shrinks to the question and what was picked; a turn's edited files and its pull request show as cards after the reply. Files it saved in its outputs folder and linked (`../outputs/…`, read by `src/core/outputs.ts`), and its screenshots, show as cards under the reply and its images inline; a link or card opens the file in the viewer beside the chat (`output-viewer.tsx`, one for the app through `src/web/lib/viewer.ts`, over the side panel when there is one), where an image can be marked up with `Sketch` and added to the composer. A project's thread rows show their files as chips with a preview (`thread-outputs.ts`), and the coordinator links one as `#thread-<id>/outputs/<path>`. With Settings › General › Visual replies on (`visualReplies`, default Some), it also has `show`: a card from a fixed catalog (`src/core/ui-spec.ts`: layout, stats, tables, charts drawn in `ui-chart.tsx`, timelines, diffs, file links, live formulas over inputs, and forms whose answer is sent as your next message), checked by `src/services/show.ts` and drawn by `show-card.tsx`; and `render_html`: one self-contained page saved in the Library under `renders/` (`src/services/renders.ts`) and shown in the thread (`html-frame.tsx`). A page reaches no network itself: it is served with a sandboxing CSP that allows no requests, inside a frame page whose CSP lets it load only Anton's origin, and it talks to the thread over the MCP Apps postMessage protocol (its height, links the user agrees to open, and `window.anton.send` text for the composer). Its `fetch()` for http(s) goes the same way: the frame page has Anton make the request (`src/services/page-fetch.ts`: public addresses only, checked as each connection is made, no cookies, size and time limits), so pages can call web APIs whatever their CORS rules; Settings › General › Pages reach the web (`pageNetwork`, default on) turns it off. A page is a small app whose state lives on the server (`pages` in `src/db/pages.ts`): it keeps it with `window.anton.setState`, or has its form fields kept for it, and every copy (the thread, a tab of its own, the Library, Artifacts) shows the same state: the frame page, not the page, saves it (`PUT /api/sessions/:id/page-state`), and hears of other copies' saves from the thread (`onPageChange` in `live-updates.ts`, from `{ kind: 'page' }` changes) or, in a tab of its own, from `/api/events`. Any HTML file in a Library shows as such a page, with its source a click away: the stylesheets, scripts, images and fonts it names from its own folder are put into it as it is served (`page-assets.ts`), and it gets a localStorage kept with its state (`storage`), so an app written as several files works there too. A card answers by the user's next message, so a reload still shows what was picked. With an OpenRouter key the Coder also has `generate_image` (`src/services/images.ts`, the `ImageModel` port, OpenRouter's Images API in `src/providers/openrouter/images.ts`): whatever model the task runs on (a ChatGPT plan's route and Claude Code offer no image tool of their own), an image model draws the picture, the task's own when it is one, else Settings › General › Image model (`imageModel`), else `ANTON_IMAGE_MODEL`; it can start from Library images (`from`), is kept under `images/`, counted in the task's and the reply's spend, and drawn in the thread where it was made (`ImageBlock` in `thread.tsx`, a checkerboard under a transparent one) rather than again among the reply's files.
- The Artifacts page (`artifacts-page.tsx`, Artifacts in the sidebar) gathers what the agent made in every task (`src/services/artifacts.ts`; not your uploads): apps first, as static cards (a live app runs only when opened), then documents, images, data and code (`src/web/lib/artifacts.ts`), each opening full size with its source. Each task's Library is listed from storage once and kept in `output_index` until checkpoints.ts forgets it on a change. Gallery image/text previews mount only near the viewport and unmount on leaving it; images over 2 MB stay as file faces until opened. Select adds checkboxes, select-all-shown and a hidden-selection count across filters. Selected files download as one ZIP (`artifact-archive.ts`, at most 500 files and 50 MB), with paths kept under separate task folders; missing files fail the download rather than silently disappearing. Bulk Delete asks for confirmation, runs at most three deletes at once, and leaves failures selected for retry. An artifact can also be deleted from its card's menu or its full-size view (asking twice); that is `removeOutput` in `files.ts`, as Library's Delete, which also keeps the path in `deleted_outputs`, so the task's `outputs` view lists it under `deleted` (until the agent saves that path again). A reply that drew, linked or carded a deleted file says so (`DeletedArtifact` in `output-viewer.tsx`, `useDeletedOutput` in `src/web/lib/deleted-outputs.ts`) rather than showing a broken image or page, and so does the viewer.
- Attachments: every composer (a task's thread, New task, the coordinator, a new thread) shares `useAttachments` (`src/web/components/attachments.tsx`): the paperclip, paste or drop takes any file. Images the model can see go with the message as images; every other file is uploaded as the message is sent (`src/services/attachments.ts`), saved to the task's Library under `uploads/` (the coordinator's and a new thread's to the project's Library) and read as text by `documents.ts` (officeparser turns PDFs and office documents into Markdown, SheetJS spreadsheets into a CSV per sheet, UTF-8 files are read as they are). The message carries each as an `<attachment>` block after the typed text, cut at 20,000 characters (`src/core/attachments.ts`), which the thread shows as a chip; the agent reads the rest with `read_attachment` (`read_project_file` for project files), and `copyUploads` puts the originals in the sandbox's outputs folder when it starts, for the agent's own tools.
