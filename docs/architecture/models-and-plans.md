# Models and plans

Linked from [AGENTS.md](../../AGENTS.md).

## Plans and gateways

- `src/services/models/subscriptions.ts` keeps and renews each plan's sign-in or key, adds the plan's models (marked PLAN in the picker) and counts use (`planUsage`). Plan calls are recorded at $0, or at API prices toward the spending caps when that option is on.
- Settings › Subscriptions is `src/web/components/settings/subscriptions.tsx` (the page and sign-in plans such as ChatGPT); Claude, key plans and gateways are in `subscriptions-claude.tsx`, `subscriptions-key.tsx` and `subscriptions-gateway.tsx`, shared pieces in `subscriptions-parts.tsx`.
- ChatGPT (`src/providers/chatgpt/`, models `openai/<model>`): Sign in with ChatGPT; calls go to the Responses API with the plan's token. OpenAI only redirects to `http://127.0.0.1:1455/auth/callback`: Anton catches it when local, and the user pastes it when hosted. An `auth.json` from `npx @earendil-works/pi-ai@latest login openai` can be pasted instead.
- Google Antigravity (`antigravity/<model>`): an ACP runtime like Devin — `agy acp` jailed in a Modal container, its own agent loop and tools inside the jail, Anton's tools over MCP ([acp-runtime](acp-runtime.md)). Sign in is Google OAuth (Antigravity's own client) writing agy's token-file shape on the host; the container gets only that file. Models come from `session/new`'s `configOptions` (base ids like `gemini-4-neon`; effort rides `thought_level`). Consumer Google AI plans prohibit driving Antigravity from a third-party agent harness — the user's call, same as `agy` itself; the Gemini API key path stays the supported one.
- Claude (`claude-code/<model>`): Pro and Max plans work only inside Claude Code, so Anton runs it on the server with its built-in tools off and Anton running every tool; signed in through its own `auth login`. Anton never holds that token and never passes Claude Code an API key or `CLAUDE_CODE_OAUTH_TOKEN`. Design, policy and limits: [claude-code-plan](claude-code-plan.md).
- Key plans (`KeyPlan`): OpenCode Go (`opencode-go/<model>`, called directly on its OpenAI- and Anthropic-shaped endpoints) and Cursor (`cursor/<model>`, run through the Cursor SDK on the server like Claude Code, its own tools off; no per-token prices, so recorded at $0). The key is checked with the vendor and kept in settings, never in a machine.
- Gateways (`gateways` in `src/providers/index.ts`): OpenRouter and Vercel AI Gateway, each a pasted key or else its environment variable; a pasted key wins and disconnecting it falls back to the environment's. Without an OpenRouter key its models leave the picker. Agents, the decision model and the vision model call OpenRouter; only agents call Vercel (`vercel/<creator>/<model>`).
- A model choice's route (`src/core/model-route.ts`) is `<model>#via=<slug>` (a provider tried first, with the gateway's own fallback: OpenRouter `provider.order` + `allow_fallbacks`, Vercel `providerOptions.gateway.order`) or `#sort=<price|throughput|latency>`; the two exclude each other, belong to one task, and a provider is dropped when the model changes. Usage counts under the plain model. Settings, project choices and automations round-trip the specifier; task records keep the plain model and the route apart. Runtime specifiers for helpers, coordinators and compaction are registered by scope (`src/core/routed-models.ts`); the registry never picks a route, only the caller's specifier does.
- Variants: `<model>[1m]`, `<model>[fast]` and both are models of their own (`src/core/model-variants.ts`); fast on ChatGPT sends `service_tier: "priority"`.

## Rules

- A model's maker (for its tool profile, see [agents](agents.md)) is read from its specifier alone (`madeByOpenAi` in `src/core/tool-profile.ts`), never from the model list, so it never waits on a vendor and is stable across renders. `openai/` is OpenAI and `claude-code/` Anthropic; on OpenRouter and Vercel it is the id's first part (`openrouter/openai/...`, `openrouter/~openai/...`); on multi-maker plans (Cursor, OpenCode Go, Antigravity) it is the name (`gpt-`, `codex`, `o3`, `claude-`, `gemini-`). Routes and variants are ignored.
- A reply failing on a non-default model offers Retry on the default (`isPlanRefusal`, `switchToFallbackModel`). Nothing switches by itself, since another model may bill another account.
- Background models (`backgroundModels` in `src/services/models/general.ts`): web digests, screen reading, compaction summaries, and the reply check (the finish review for a task whose own model the text port cannot run, in `src/services/replies/finish-review.ts`). Digests, screen reading and the reply check must be OpenRouter models. Each keeps its own effort (`backgroundReasoning`), sent as OpenRouter's `reasoning.effort`, or as the compaction summary's reasoning through a patch in `scripts/patch-flue.ts`. With no compaction model chosen, the conversation's own model writes the summary (the one model certain to be reachable) at `low` (`COMPACTION_SUMMARY_EFFORT`); each plan maps that level as it maps the task's thinking level. A subagent on its own model summarises with that model.
- `src/services/models/decisions.ts` is the decision model (yes/no and choices with probabilities, a fraction of a cent). Everything that uses it must behave as before without it.
