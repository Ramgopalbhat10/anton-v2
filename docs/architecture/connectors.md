# Connectors

Linked from [AGENTS.md](../../AGENTS.md).

- Settings › Connectors (`settings/connectors.tsx`, catalog in `src/web/lib/connector-catalog.ts`) turns each connector on or off for every task.
- The agent never gets a connector's tools in its tool list: `connector_tools` lists them and `connector_call` calls one (`src/services/connector-tools.ts`), reading the state as they run. Switching a connector changes neither tools nor instructions, so the prompt cache holds.
- MCP servers live in `mcp_servers` (`src/services/mcp-servers.ts`); OAuth sign-in is `mcp-sign-in.ts`. Tokens reach connections as a bearer, never a view.
- Accounts (Google, `src/providers/google/sign-in.ts`) sign in with PKCE on your own OAuth client; `src/services/connectors.ts` keeps their tokens on the server, never in a sandbox, a view or the model.
- Gmail (`src/services/mail.ts`): `gmail_send` never sends. It keeps the draft in `mail_approvals` and waits for the user's Send press (`mail-card.tsx`), which sends only if the draft is unchanged.
- Apps connected through Composio sit behind the `AppsConnector` port (`src/core/ports.ts`, implemented in `src/providers/composio/`): the platform's catalog, hosted connect links, account status and tool execution. `src/services/composio.ts` keeps one `composio_accounts` row per toolkit — the connected account's id, status and logo, never its tokens — and maps them onto connector states like a mailbox's. The project key is a `KeySlot` (`COMPOSIO_API_KEY`, or pasted in Settings), loaded at startup by `loadComposioKey`. The Connectors page's one search box filters what is offered and, a beat behind the keystrokes, asks Composio's whole catalog for more; an app it finds joins the offered tiles and opens the same add page.
- A Composio app's tools reach the agent as `composio__<toolkit>__<action>` through the same `connector_tools`/`connector_call` pair, never `run_script` (`codeMode: false`). Reads run at once; a call that would change something is kept in `tool_approvals` (`src/services/tool-approvals.ts`) and waits for the user's Run press (`tool-approval-card.tsx`), which reruns the stored call — only a leading read verb in the tool's name skips approval.
