# Models and plans

Plans signed in from Settings › Subscriptions, gateways, model variants, and the background and decision models. Linked from [AGENTS.md](../../AGENTS.md).

- `src/services/subscriptions.ts` — plans signed in to from Settings › Subscriptions: keeps each sign-in, renews its token for the agents' calls, and adds the plan's models to the list, and counts each plan's use (`planUsage`). Claude plans (`docs/claude-code-subscription.md`) are run by Claude Code on the server, which signs in through its own `auth login` into `<dataDir>/claude-code`; Anton never holds that token, and never passes Claude Code an API key or `CLAUDE_CODE_OAUTH_TOKEN`. Key plans (`connectKey`) keep a key the vendor accepted in the settings, never in a machine. OpenRouter is no plan but takes a key the same way (the `GatewayAccount` port, `src/providers/openrouter/account.ts`): `gatewayView` lists the models that key may use, paged in its tab, and `src/providers/openrouter/key.ts` hands the pasted key, else `OPENROUTER_API_KEY`, to the catalog, the agents' calls (`liveOpenRouterProvider`), the decision model and the vision model; without either, OpenRouter models leave the picker (`gatewayOffered`). Vercel AI Gateway is a second gateway the same way (`gateways` in `src/providers/index.ts`: `src/providers/vercel/`, its key slot, `liveVercelProvider` over its Anthropic Messages endpoint), for the agents only. A task's route (`src/core/model-route.ts`, `route_json` on the session) sends a gateway model's calls to one provider first or sorts them by price, throughput or latency: the Coder resolves `<model>#via=<slug>` or `<model>#sort=<sort>` (`agentModelFor`), `withRoutes` in `live-models.ts` lists those specifiers and sends each call as the plain model with the route added to the body, and usage counts it under the plain model (`unrouted`); the provider and sort menus beside each gateway model's pin in the picker (on hover; always on the chosen model) are `route-menu.tsx`, and New task keeps its route until the task is made (`createSession`'s `route`), listing providers from the catalog's `endpoints`. A key plan or Claude Code shows the plan's own limits when the vendor reports them (`windows`); ChatGPT's plan route and the Cursor SDK report none. A plan model's larger context and fast mode are models of their own to the agents, `<model>[1m]`, `<model>[fast]` and both (`withVariants` and `linkVariants` in `src/core/model-variants.ts`, which mark each with the model it is a `variant` of), and the model picker lists only that model, with a context ruler and a Fast switch above its effort (`ContextRuler`, `FastToggle`, `optionsOf` in `src/web/lib/model-catalog.ts`). They come from what the vendor's list offers: ChatGPT's `max_context_window` and `service_tiers` (fast sends `service_tier: "priority"`), Claude Code's `[1m]` models and `supportsFastMode`, Cursor's `context` and `fast` parameters. A reply that failed on a model other than the default (a plan that turned it away, as Cursor's free plan does; `isPlanRefusal` in `src/core/model-refusal.ts` says which) shows, under its error, Retry on the default model: `switchToFallbackModel` in `sessions.ts` moves the task there at the default level and the thread sends Continue. Nothing switches by itself, since another model may bill another account.
- Background models (`backgroundModels` in `src/services/general.ts`, Settings › General's Background models): the models Anton runs behind the agents for web digests, screen reading for the computer subagent, and compaction summaries (task titles have their own Title model) (`compactionFor` passes it to the runtime as its `CompactionConfig.model`), each null for its default (`backgroundDefaults`: the `ANTON_*_MODEL` variables, the task's own model for compaction). They are read synchronously through `backgroundModel`, from the settings last read (at boot and on every read or save); digests and screen reading must be OpenRouter models, and screen reading one that reads images.
- `src/services/decisions.ts` — the decision model (TypeSafe's Jev through OpenRouter, a `DecisionModel` port): yes/no and choice questions answered with probabilities for a fraction of a cent. Follow-ups and automatic reviews use it to skip work, the browser tool to trim pages and spot sign-in walls, and `reply-check.ts` to mark a task waiting on you (`asking`) when its reply asks something; without it they behave as before (a reply ending in a question still counts).
