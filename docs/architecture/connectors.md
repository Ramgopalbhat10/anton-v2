# Connectors

Settings › Connectors and how the agents reach connected services. Linked from [AGENTS.md](../../AGENTS.md).

- Connectors (Settings › Connectors, `settings/connectors.tsx`: a catalog of tiles, yours with their switch and the rest to add from `src/web/lib/connector-catalog.ts`, each opening a page of its own at `/settings/connectors/view` with its description, tools, sign-in and facts): each one on or off for every task, from that page or the + menu in any composer (`composer-plus.tsx`, `src/web/lib/connectors.ts`). The agent never gets a connector's tools in its tool list: `connector_tools` lists those of the connectors on now, the eight best matches with their arguments and the rest a line each (asked for by name for theirs), and `connector_call` calls one (`src/services/connector-tools.ts`), both reading the state as they run, so turning a connector on or off changes neither the tools nor the instructions (which name only the connectors set up) and the prompt cache holds; a connector costs context only once the agent looks it up. The thread draws a `connector_call` as the tool it ran (`src/web/lib/connector-calls.ts`). MCP servers live in `mcp_servers` (`src/services/mcp-servers.ts`; a repository's own were moved there by migration 29; `enabled` is the switch). A server takes a pasted token or signs in with OAuth (`src/services/mcp-sign-in.ts`, the MCP SDK's `auth()`: discovery, dynamic client registration or a client you paste, PKCE; its requests go through `signInFetch`, since Hono's Node server swaps the global `Response` the SDK checks to read a refusal, and a pasted client's secret goes in the form where the server lists no way to send it, as GitHub's needs), returning to `/api/mcp-servers/callback`; its tokens stay in `oauth_json`, are renewed before each message, and reach the agent's connections as a bearer, never a view; a server whose sign-in was refused is left out until you sign in again. Accounts (`AccountSignIn` port, Google in `src/providers/google/sign-in.ts`) sign in with PKCE on your own OAuth client, pasted in Settings or `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`, returning to `/api/connectors/<account>/callback` on the origin the browser sent; `src/services/connectors.ts` keeps and renews the sign-in on the server, and its tokens never reach a sandbox, a view or the model. Gmail (`Mailbox` port, `src/providers/google/gmail.ts` over the REST API) offers `gmail_search`, `gmail_read_thread`, `gmail_draft` and `gmail_send` through `connector_call` (`src/services/mail.ts`), as allowed by the sign-in's scopes and the page's switches. `gmail_send` never sends: it keeps the draft as it stands in `mail_approvals`, marks the task waiting on you, and the thread draws it with Send and Don't send (`mail-card.tsx`); only that press sends it, from Anton, and only if the draft is still what you were shown.
