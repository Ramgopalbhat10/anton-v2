# Development notes

Linked from [AGENTS.md](../../AGENTS.md).

- `npm install` runs `scripts/patch-flue.ts`, which patches Flue bugs: duplicate skill names with `.agents/skills`, subagents copying their parent's compaction reserve, `flue.db` opened without a busy timeout, transactions opened with a plain `BEGIN` (a reader is refused a held write lock at once whatever the timeout, so they open with `BEGIN IMMEDIATE`), and `CANONICAL_FLUSH_DELAY_MS` lowered from 1000 ms to 100 ms (with delta-only batches weighted 0.1 toward fold checkpoints so checkpoint frequency stays ~64 s) so streamed replies arrive smoothly instead of in 1-second bursts. Drop each patch once Flue fixes it.
- `npm run lint:hooks` runs oxlint's React hooks rules on `src/web` (`.oxlintrc.json`), in CI too. Breaking the rules of hooks fails it; a missing effect dependency is only a warning, since some effects leave one out on purpose.
- `npm run ui:fixture` serves the real UI on Vite with `@flue/sdk` swapped for scripted conversations (`scripts/ui/chat-sdk.ts`) and the API mocked (`scripts/perf/mock-api.ts`). A request with no mocked answer logs `[perf] unmocked`; a page that reads a field of that empty answer fails, so add the answer there. In a task's sandbox it binds the first of `$ANTON_PREVIEW_PORTS` (so Preview shows it), else `UI_FIXTURE_PORT` or 43160. Every conversation (`/agents/perf-task`, `/incognito`, a project's coordinator) starts with 8 long turns (`?turns=0` or `?turns=20` to change it). A project's coordinator with `?reports` adds thread reports: answered ones show as chips in the reply, an unanswered one as its own line. `?reports=deleted` adds a thread the coordinator started and reported on, since deleted. A thread's menu deletes it after 3 seconds, as a real delete takes a while. A Playwright script drives it through `window.__chat`: `send(text?, { chars, ms })` and `reply(...)` resolve once the reply settles; `streaming()` and `info()` report. Use it to check layout, scrolling and streaming in seconds.
- `scripts/perf/profile.ts` profiles a task page in Chromium with a scripted reply (no keys); it uses `PERF_CHROMIUM`, else the newest Chromium under `/opt/pw-browsers`.
- The UI fixture can stream exact Markdown with `window.__chat.reply({ text, ms: 40 })`. `scripts/ui/artifact-fixture.ts` supplies a long-name image, PDF and long Markdown report through the mocked output endpoints for viewer layout checks.
- The UI fixture's session is not permanently marked working (the performance fixture's is); scripted SDK submissions and streams drive its lifecycle, so a completed reply returns to idle.
- Open `/projects/space-billing?turns=0&joined-todos` in the UI fixture to see two board handoffs answered by one coordinator reply, with a rejected attempt before the second thread starts. Use `joined-todos=inferred` to see a handoff that joins ordinary chat and whose thread start infers the to-do ID.
- `node scripts/ui/sidebar-layout.cjs <fixture-url> [screenshots-dir]` checks a collapsed desktop project sidebar resized into the mobile drawer: menu placement and viewport bounds at 390px, 320px, 767px and back across 768px, including an open menu. Set `PERF_CHROMIUM` if Chromium is not in Playwright's default location.
- `node scripts/ui/library-pdf-layout.cjs <fixture-url>` checks that a PDF opened from the thread Library at 320px fits its preview and fills the space below the file header. Run it against `npm run ui:fixture` with full Chromium installed (`npx playwright-core install --no-shell chromium`), or set `PERF_CHROMIUM` to the full browser’s executable.
- `npx flue run src/agents/coder/index.ts --message "Say ready."` tries the Coder (needs an LLM key).
- Production: `npm run build && npm start` on `PORT`. `npm run start:backup` (`scripts/start-with-backup.sh`, settings in `litestream.yml`) needs Litestream 0.5+ and the Tigris variables: it restores `anton.db` and `flue.db` from `db/` in the bucket when the server has none, then runs Anton under Litestream (writes streamed every 30 s, the last flushed on a clean stop). If the restore fails Anton does not start, since an empty database beside existing storage would lose every task. Only one server may run against a bucket at a time.
