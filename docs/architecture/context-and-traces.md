# Context, compaction and traces

How a task's context window is measured, cut, pruned and compacted, and how each reply's trace is kept. Linked from [AGENTS.md](../../AGENTS.md).

- `src/services/context-usage.ts` measures each task's context window from the runtime's `turn_request` and `turn` events (the composer's context meter), and sets where the agents compact (`compactionFor`): at Settings › General's Compact at (`compactAt`, 200K by default) when that comes before the window less the runtime's reserve, since every call sends the whole conversation, tool results included. A compaction keeps a fifth of the context it compacts at word for word (8K to 40K, `keptAfterCompaction`; the runtime keeps 8K), so the agent does not read again the files it was working from. For the same reason a tool result past 50KB (a connector, a script, a subagent's answer; the runtime's read and bash cut their own), a web search past 12KB or a web fetch past 24KB (`LIMITS`) keeps its first part and a note where it joins the coder's, reviewer's or a coordinator's conversation (`src/flue/tool-result-cut.ts`, an execution interceptor), and the agent reads on with `read_full_result` (`src/services/tool-results.ts`, the latest 20 kept per conversation in memory). A long web search or fetch is instead read out against the call's objective by a fast model (`src/services/web-digest.ts`, the `TextModel` port, Settings › General's background models else `ANTON_WEB_DIGEST_MODEL`, Gemini Flash Lite by default for its 2 to 3 seconds, `off` to cut instead; the objective comes from the call's `tool_start` event, `recordWebCall`), with the whole kept for `read_full_result`, and is cut as before when there is no model or objective, when the digest would cost more than the tokens it saves on the task's model (`digestPays`: never for a model as cheap as the digest model, or a plan model with no price), or when the model fails or takes over 8 seconds. A subagent's own calls, which cannot read on, get the digest alone or keep their start and end (`cutHeadAndTail`, 24KB at most). An activated skill (`activate_skill`) lists its supporting files once per folder rather than a packaged path each, and instructions past 32KB keep their first 16KB and a list of later sections with offsets for `read_full_result` (`src/services/skill-parts.ts`); a subagent's skill is never cut. Past half of where an agent compacts (`compactionPoint`), a model call sends its oldest tool results, beyond the newest 20K tokens of them, as one-line stubs, down to 30% (`src/services/context-prune.ts`, through `withPruning` in `src/flue/pruned-models.ts` on the gateway, ChatGPT and OpenCode Go providers, never Claude Code's or Cursor's, which match what they are sent against their own conversation): in batches, and while the prompt cache is warm only where a batch pays back its miss by the model's prices (`warmShare`: half the mark where the cache takes about 90% off, as Claude's and GPT's do, and 85% where it takes 98% off, as DeepSeek's does, or without prices), and once the conversation has made as many calls as that batch takes to pay back, so a short chat waits for 85%; reasoning written before the newest cleared result is left out with it on Chat Completions and Anthropic Messages APIs (`THINKING_OPTIONAL`), never on the Responses API, which wants each tool call's reasoning item; and what was cleared stays cleared so the cache holds between batches; the runtime's conversation stays whole, and `read_full_result` reads a cleared result again. A reply's footer counts every call it made (`src/services/response-usage.ts`), so it carries the largest context one call held against the window, its compactions, and whether Cursor's counts were estimated; `latest-input.ts` keeps each task's latest input, recorded by the Coder for every message it is given (`useDelivery` in `useAgentStart`; the runtime emits no event for delivered messages), and fills in older tasks once at start from the runtime's accepted submissions.
- `src/services/response-trace.ts` records each Coder reply's trace from the runtime's events (`src/core/trace.ts`): every model call (its request split into system prompt, skills, tools, MCP tools and messages, the messages it added since its conversation's previous call, cache reads and writes, output) and tool call (input and output, cut to sizes that stay readable), each subagent's under the `task` call that started it, on one clock. It is saved in `response_traces` as the reply finishes (the latest 100 per task, `src/db/traces.ts`), and the reply's metadata carries its `traceId`. The trace modal (`trace-modal.tsx`, laid out by `src/web/lib/trace-view.ts`), opened from the reply's footer or its usage peek, draws it as a timeline with the reply's totals and a card for the step picked. Its timeline stretches past the modal's width (Auto sizes the median model call to read, `autoZoom`; Fit, a slider, a drag handle at its end, Ctrl/⌘+wheel) and scrolls sideways under a sticky, resizable steps column; each model call carries its vendor's logo and gateway, and `modelChanges` marks where a conversation's model (`model`, or the provider's `served`) changed mid-run. `cacheVerdict` says why a call's cache hit or missed (a changed system prompt or tool list against the call before, else an expired or absent cache).
