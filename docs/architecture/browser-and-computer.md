# Browser and Computer panels

The hosted browser, the sandbox's headless browser and its desktop. Linked from [AGENTS.md](../../AGENTS.md).

- `src/services/live-browser.ts` — the Browser panel: a hosted browser per task (the `BrowserHost` port, Kernel in `src/providers/kernel/`, on with `KERNEL_API_KEY`), shown through its live view and driven over the Chrome DevTools Protocol (`src/core/cdp.ts`) for the address bar, picking an element (`describe-element.ts` runs in the page: HTML, selector, styles, React components and their files) and screenshots to draw on (`src/web/components/sketch.tsx`). Picks and drawings reach the composer through `src/web/lib/composer-inbox.ts`. Opening it never starts the sandbox. Kernel bills a browser for every second anything is connected to it, so Anton lets its connections go 15 seconds after their last use (the browser stands by, free, with its pages and sign-ins), stays connected only while the panel says its live view is on screen (`watchBrowser`), and the panel pauses the live view in a hidden window or after five quiet minutes.
- `src/services/computer.ts` — the Computer panel and the agent's computer: a desktop inside the task's own sandbox (`src/core/desktop.ts`: TigerVNC's Xvnc, Openbox, websockify, xdotool and ImageMagick, in the Modal image and installed on first use in older machines, started lazily and detached from the step's tag so Stop leaves it), dressed as a computer by `desktop-look.ts`: a wallpaper drawn in code (Anton's cube mark wired to the machines it runs, in Signal Cyan), a tint2 taskbar with launchers and a clock, PCManFM's desktop icons (Workspace, Files, Terminal, Text Editor, Web Browser) and dark apps, all set up in the desktop's own folder and reached through `XDG_*` variables, so a local machine's own settings are never touched. The panel (`computer-tab.tsx`) shows it with noVNC over a short-lived credentialed WebSocket from `Machine.socketUrl` (Modal connect tokens; local machines listen on this computer alone), never starts the sandbox by being viewed, and pauses after five quiet minutes; Take over makes the agent's steps wait until you give it back, and Turn off closes the desktop (not while the agent uses it). On Modal an open screen connection keeps the sandbox from idling out and a running desktop alone does not, so a paused or turned-off computer lets the sandbox stop after its idle minutes. The Coder's `computer` subagent drives it one step at a time (steps run in call order) and sees through `src/services/vision.ts` (a `VisionModel` port, OpenRouter, no tools): the agent names what to click in words, the vision model finds it on the screenshot and says what the screen then shows. The sandbox's own browser (`browser.ts`) always runs headless and never waits on the desktop: its server also serves a live view, a WebSocket (framing written out in the script, on a port a thousand above the desktop's socket) that streams the tab as JPEG frames from Chromium's screencast while anyone watches and takes your mouse and keyboard as Playwright input; the panel shows it on a canvas (`BrowserScreen`, through `connectBrowser` and the same `Machine.socketUrl`), switching with the desktop when both run, and Take over holds the agent's browser steps as it does its computer steps (`browseOnComputer`, one queue). A repository's Full VM setting (`fullVm`) runs its sandboxes as Modal VMs (`runtime: 'vm'`) for Docker and FUSE.
