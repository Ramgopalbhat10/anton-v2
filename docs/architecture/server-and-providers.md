# Server, providers and Flue

Linked from [AGENTS.md](../../AGENTS.md).

- `src/core/ports.ts` — the interfaces every provider implements (sandbox, object store, git host, model catalog, plans). `src/providers/index.ts` picks implementations from config.
- `src/providers/` — Modal, Docker, local, S3, disk, GitHub, OpenRouter, Vercel, and the plans: ChatGPT, Claude Code (`claude-code/runtime.ts`, the only file importing the Claude Agent SDK), OpenCode Go and Cursor (`cursor/plan.ts`, the only file importing `@cursor/sdk`).
- `src/flue/` — adapters into Flue: the machine sandbox driver, `live-models.ts` (any catalog model resolves), and the plan bridges (`subscription-models.ts`, `opencode-go-models.ts`, `claude-code-models.ts`). `src/agents/providers.ts` registers them with `setProvider` once; each agent imports it for that side effect.
- Whole files (`src/core/machine-fs.ts`): `readMachineFile` and `writeMachineFile` use the machine's own file access when it has one (`Machine.readFile`, `writeFile` in the port), else a command (`wc -c` and `cat`, `cat >`), which every provider has. A login shell per file costs most where a command is a network round trip, and `read`, `edit`, `write` and `apply_patch` each read or write whole files. The local machine reads and writes with Node; Modal's file API (`sandbox.filesystem`) is behind `ANTON_SANDBOX_FILE_API=1`, off until it has been tried on a real sandbox, since it takes absolute paths only, has a read size limit and makes the folders a write lacks, where `cat >` fails. A relative path, a file past the limit or an error it does not name go to the command. Docker has no file access of its own. Either way a failure is the same `CommandError`, naming the operation, path and reason (`fileError`).
- `src/db/` — libSQL client, versioned migrations, queries; `adapter.ts` is Flue's persistence entry (`db` in `flue.config.ts`). `src/app.ts` — Hono routes. `src/server.ts` — production server.
- Gotcha: Cloudflare closes a request at 100 seconds, so Stop and Delete answer by `ANSWER_MS` and finish behind the answer (`answer-within.ts`).
- Gotcha: Cursor moves tool results over 40KB into a file its own (disabled) tools would read, so `cursor/plan.ts` hands long results back in parts through `read_tool_output`, and gives each agent an in-memory store, since the SDK's JSONL store rereads its whole file per update.
- Settings › Connections is also the setup (`src/services/setup.ts`, routes `/api/setup`): each slot (models, code host, sandboxes, object storage, database, decision model, web search) lists its providers and the values each needs, with where each comes from now. Test (`POST /api/setup/:slot/test`) checks values without keeping them (`src/providers/checks.ts`: one function per provider); Save checks again, then keeps them. Model keys go where Settings › Subscriptions keeps them (`connectKey`); every other value goes to `<dataDir>/anton.env` under its environment variable (`src/saved-env.ts`), which `config.ts` lays over the environment before reading any setting, and removing one gives the environment's value back. A secret never goes back to the page, only its last four characters. The database URL is in that file, so it is a file and not a row.
- Live or at the next start: the GitHub token and API address, the decision model and the web search server are getters on `config`, and saving one rebuilds the code host and decision model (`refreshLiveProviders`). The sandbox, object store and database are chosen once in `getProviders()`, so saving one says Needs a restart until the server starts again; there is no restart route.
- Gotcha: a check that gets no answer in 10 seconds (`withTimeout` in `connections.ts`) retraces the request (`why-no-answer.ts`): the address lookup, then a connection to each address, and says which was slow. Node looks names up on a pool of 4 threads, so a slow resolver stalls every new request from the server at once; it showed as GitHub, S3 and the decision model failing together while Modal (an open connection) and the model list (cached) passed. Each failure also goes to Recent problems.
